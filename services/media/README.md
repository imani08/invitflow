# Media service

The service owns `media_db` and asset lifecycle metadata. Authenticated routes are exposed through the Gateway and Web BFF at `/api/assets`:

- `POST /api/assets` reserves an owner-scoped image asset (`filename`, `mimeType`, `sizeBytes`, `purpose`). Only PNG/JPEG/WebP up to 5 MiB are accepted.
- `POST /api/assets/:id/upload-url` issues a 5-minute S3 POST policy scoped to one quarantine key, exact MIME type and the declared byte limit. The browser posts the returned fields and file directly to that URL.
- `POST /api/assets/:id/complete` verifies the stored byte count and MIME, checks magic bytes and image structure, enforces dimension/pixel limits, rejects animation and trailing payloads, scans the file with ClamAV over the framed `INSTREAM` protocol, then decodes the pixels with Sharp, applies EXIF orientation, and strips metadata by re-encoding three WebP sizes: original (at most 4096 × 4096), preview (at most 1280 × 1280), and thumbnail (at most 320 × 320). Malware is rejected and removed before decoding; scanner failures keep the upload retryable and never mark it ready. The asset becomes `READY` only after all variants are stored in the private ready bucket; incomplete publications are deleted. Completion is idempotent after an asset reaches `READY`.
- `POST /api/assets/:id/download-url?variant=original|preview|thumbnail` signs downloads only for fixed variants of owner-scoped `READY` assets; omitting `variant` selects the original.
- `DELETE /api/assets/:id` removes stored objects and tombstones the owner’s record.

Every metadata operation filters by the verified Keycloak subject. Unknown and foreign asset IDs return the same not-found response. Failed and abandoned uploads expire and are removed; a leftover raw upload is also cleaned after its signed intent expires. Upload intents expire after ten minutes and each signed POST lasts at most five minutes. The browser can write only to the quarantine bucket and cannot overwrite ready assets. `MINIO_PUBLIC_ENDPOINT` must be reachable by browsers and identify the same S3-compatible bucket service as `MINIO_ENDPOINT`.

`image-validation.mjs`, `antivirus-scan.mjs`, `image-transcode.mjs` and `s3-presign.mjs` have unit coverage, including the ClamAV framing/clean/infected/error responses, pixel decode, metadata stripping, variant bounds, malformed input rejection and an independent SigV4 calculation for the short-lived ready-asset GET URL. Development Compose uses the official ClamAV 1.5.4 image on a scanner-only internal network, with a separate egress network for signature updates. Production must provide a trusted ClamAV-compatible endpoint through `MEDIA_ANTIVIRUS_HOST` and optional `MEDIA_ANTIVIRUS_PORT` (default `3310`); the TCP connection must remain on a private trusted network because the clamd protocol has no transport encryption. Runtime behavior still needs verification against running PostgreSQL, Keycloak, MinIO and ClamAV.

The Compose `media-db-init` job creates the dedicated role on both new and existing PostgreSQL volumes. `media-keycloak-init` adds the `media-api` audience to the web client on both fresh and persistent realms. `minio-bootstrap` creates the quarantine bucket, service account, restricted policy and short-lived signed-POST CORS rules.
